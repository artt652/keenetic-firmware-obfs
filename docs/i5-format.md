# Настройки wg-obfuscator в параметре I5

Модифицированный модуль WireGuard получает настройки wg-obfuscator через параметр AmneziaWG `I5`.
NDM передаёт его в ядро как есть, так что обфускатор настраивается штатно: импортом `.conf`,
в веб-интерфейсе или командой CLI.

## Формат (версия 1)

```
<b 0x 57474F42  01   01   0004   6A6E4431…>
      «WGOB»   вер. маск. dummy  ключ
```

| Поле | Байт | Значение |
| --- | --- | --- |
| метка | 4 | `57 47 4F 42` («WGOB») |
| версия | 1 | `01` |
| маскировка | 1 | `00` NONE, `01` STUN |
| max-dummy | 2 | big-endian, 0–1024 |
| ключ | 1–255 | UTF-8, без `#` и `=` (как у wg-obfuscator) |

Строку собирает `tools/wgobfs-i5.sh <ключ> [NONE|STUN] [max-dummy]`.

Модуль, увидев метку `WGOB` в I5, включает режим wg-obfuscator и **не** отправляет I5 как
пакет-приманку. Остальные параметры AmneziaWG при этом должны быть нейтральными
(`Jc 0`, `S1`–`S4 0`, `H1`–`H4 = 1 2 3 4`, `I1`–`I4` пустые): серверный wg-obfuscator понимает
только стандартные заголовки WireGuard.

## Проверено на KeeneticOS (Titan)

- произвольный текст в I5 NDM отклоняет: `invalid I5 value`;
- `<b 0x…>` длиной 71 байт принимается и сохраняется в `running-config` без изменений.

Команда CLI (порядок: Jc Jmin Jmax S1 S2 H1 H2 H3 H4 S3 S4 I1 I2 I3 I4 I5):

```
interface Wireguard0 wireguard asc 0 0 0 0 0 1 2 3 4 0 0 "" "" "" "" "<b 0x57474F42…>"
system configuration save
```
